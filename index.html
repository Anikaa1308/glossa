    Practice

    The AI writes three questions about this translation.

    This runs 15 test sentences through two prompting strategies, scores each result against a reference gloss with code, and then asks a separate AI call to judge both. It is the evidence for your report: which approach gives better ASL grammar.

    The reference glosses were written for this demo from standard ASL grammar rules. Real ASL has more than one correct gloss for most sentences, so treat the scores as relative. For final results, replace the references with ones checked by a fluent signer or a published dataset.

    The pipeline

    • Stage 1, grammar. A language model gets the sentence plus ASL rules and worked examples. It returns gloss tokens and a list of the changes it made.
    • Stage 2, self-check. A reviewer call reads the gloss back into English, checks the meaning survived, lists grammar problems and returns a corrected gloss. This is a generate-then-critique loop.
    • Stage 3, sign planning. Another call turns every gloss token into structured sign details: handshape, orientation, location, movement, facial expression.
    • Stage 4, preview. Code maps location and movement to a moving dot on a body outline.
    • Extras. A streaming tutor chat, AI-chosen handshapes drawn from a library of standard ASL shapes with a confidence rating, AI-written practice quizzes, and an AI judge in the evaluation.

    Design choices

    • Structured JSON between stages, so every stage can be tested on its own.
    • The model picks a handshape from a fixed list of standard ASL shapes and my code draws it. Letting a model draw hands freehand produced unreliable shapes, so it only chooses.
    • Rules and few-shot examples are compared against a plain prompt on the Evaluate tab.
    • If a model response is malformed or incomplete, the app fills the gaps and keeps going. Unknown words fall back to fingerspelling.
    • The model never sees user data beyond the sentence typed.

    Limitations

    • The preview is a schematic, not video of a signer. Sign details come from the model's knowledge and can be wrong, so they should be checked before real use.
    • Gloss is a written approximation. It cannot show facial grammar, body shift or speed, which carry real meaning in ASL.
    • One sentence at a time, with no memory of earlier ones.
    • Built with input from no Deaf signers yet. Any real deployment should involve the Deaf community.

    Future scope

    • Retrieve real sign video from a licensed dataset and match words by meaning with embeddings.
    • Drive a 3D avatar from pose keypoints instead of a dot.
    • Add the reverse direction: camera, pose detection, then ASL to English.
    • Evaluate with fluent signers and a published gloss corpus.
